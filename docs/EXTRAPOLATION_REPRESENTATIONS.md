# D127 candidate: paired LINCS transfer benchmark at three resolutions

## Scope and provenance

This is a **strict post-processing extension** to `scripts/77_lincs_extrapolation_test.py`. It **does not** generate fresh held-out splits, reselect LINCS signatures, reaggregate dose/time, or change the original Celligner source-line choices. It reads:

- `results/lincs/extrapolation_lolo_pairs.tsv` (exact held-out `(pert_id, ModelID)` keys),
- `data/processed/lincs/specific_profiles.npy` and `active_profiles_index.tsv.gz` (same indexed, generic-response-removed 978-landmark signatures),
- `data/processed/celligner/dist_line_line.tsv.gz` (original distance matrix),
- your existing **signed regulon network** exported as an edge table, and
- the **ordered landmark-gene metadata** from `scripts/76_lincs_level5_subset.py`, matching columns of `specific_profiles.npy` exactly.

The extension is a new `77b` file so the original `77` stays intact and its published numbers remain directly reproducible. `77b` compares representations on **the same pairs**. It does not by itself train a new cross-cell-line model, and it does not produce a new therapeutic-rescue score.

## Run

From the repository root in the same `celligner` environment used by `77`:

```bash
# Step 1 (skip if existing outputs of script 77 are current):
python scripts/77_lincs_extrapolation_test.py

# Step 2: export an existing VIPER-compatible regulon object to a signed edge TSV.
# Pick the correct network from your current RDS; use '-' only for a direct TF list.
Rscript scripts/77b_export_regulon_edges.R \
  data/processed/step5/regulons_aracne_project_v2_tf.rds \
  YOUR_NETWORK_NAME \
  data/processed/lincs/benchmark_edges.tsv

# Step 3: use the existing script 76 landmark-gene metadata (ordered).
python scripts/77b_lincs_representation_transfer.py \
  --edges data/processed/lincs/benchmark_edges.tsv
```

**Before running:** inspect the ordered gene list and the edge table to ensure identifiers are of the same kind (gene symbols vs Entrez IDs). Failing to map identifiers properly can eliminate most edges. The command does **not** guess gene identity from array position. `data/processed/lincs/level5_landmark_genes.tsv` is generated by script 76 and its `gene_symbol` column is in the exact `.npy` column order. The edge file is `regulator<TAB>target<TAB>sign<TAB>confidence` (`+1/-1`, positive confidence). For ARACNe/VIPER, `tfmode` gives the sign and its magnitude times `likelihood` gives an optional edge-strength proxy. Network edge strength is **not** a disease/drug expression fold change.

For a genuine VIPER comparison (recommended, rather than calling a linear proxy VIPER), export a `drug x cell line` VIPER matrix recomputed on **the same specific profiles**. Provide `--activity-matrix`, `--activity-index` with `pert_id,ModelID`, and `--activity-ids` with one TF per column in correct order:

```bash
python scripts/77b_lincs_representation_transfer.py \
  --edges data/processed/lincs/benchmark_edges.tsv \
  --activity-matrix data/processed/lincs/viper_specific_for_77.npy \
  --activity-index data/processed/lincs/viper_specific_for_77_index.tsv \
  --activity-ids data/processed/lincs/viper_specific_for_77_regulators.txt \
  --activity-label VIPER_specific
```

This is deliberately **not** hard-wired to your `drug_viper_specific_v2_tf/<NET>.f32` files because their row-index files, network-specific TF sets, and file memory layout have to be verified. A `.f32` file can be supplied, with `--activity-layout F` if written by R as column-major bytes. `77b` checks shapes and aligns rows by `(pert_id, ModelID)` and columns by TF ID; it fails on missing keys. VIPER calculated on **raw** rather than *specific* drug profiles does not constitute a fair comparison with original `77`.

If the benchmark is intended across diseases using different ARACNe networks, repeat the **same pair table** separately for each network and state that results are network-specific. A single CollecTRI network can serve as a standardized context-free comparison. Do **not** concatenate network-specific disease VIPER activities with mismatched TF definitions.

## Representations and metrics

| Evaluation | Input representation | Primary output |
|---|---|---|
| Gene level | Original residualized 978-gene LINCS response | `gene_r`: Pearson across genes |
| Activity level | Signed target-weighted linear projection, or aligned external VIPER values | `activity_r`: Pearson across regulators |
| Hierarchical target level | Every signed target within every regulon, with confidence and cross-regulon-overlap weights | `regulon_target_median_r`, `regulon_target_mean_r`, `regulon_target_frac_positive` |
| Joint consistency | Target-wise per-regulon r **and** regulator-level direction agreement | `joint_regulon_fraction`: share of valid TFs with target r > 0.3 and correct TF direction |

The activity projection without `--activity-matrix` is **not VIPER**, NES, or a retrained model: each regulator is the L2-normalized sum of its signed, confidence-weighted target-gene changes. That is an interpretable baseline, useful even if the project later supplies real VIPER profiles.

For regulator *i* and target *j*, let the fixed network provide `sign_ij` and `confidence_ij`. For each pair's observed/predicted gene-change vectors `y` and `ŷ`, define signed values `sign_ij y_j` and `sign_ij ŷ_j`. `77b` measures their **confidence-weighted Pearson correlation within each regulon**, using weight `confidence_ij / (# of regulators that include gene j)`. It reports the median of all valid regulon correlations and the fraction above zero. This is a gene-preserving metric, not a compressed TF score. Confidence and signs remain fixed across disease/drug.

The joint consistency metric is a diagnostic, not a causal or mechanistic proof: regulator activities computed from the same targets will partly agree by construction. VIPER/target consistency must not be interpreted as independent evidence if both are derived from the same expression values.

## Outputs (all additional; never overwrite `77`)

- `results/lincs/extrapolation_representation_pairs.tsv.gz` — one row per held-out drug/line/predictor; gene, activity, hierarchical and joint metrics.
- `results/lincs/extrapolation_representation_summary.tsv` — per-method medians for all metrics and number of pairs.
- `results/lincs/extrapolation_representation_by_line.tsv` — same metrics stratified by held-out cell line.
- `results/lincs/extrapolation_regulon_coverage.tsv` — regulator count and matched landmark target coverage.
- `results/lincs/extrapolation_representation_manifest.json` — provenance, count checks and caveats.

The script validates that reconstructed `nearest` and `mean` **gene-level Pearson correlations reproduce the original `77` pair-table values** within a small numerical/rounding tolerance. It also checks the weighted-tau results if present. If these invariance checks fail, the extension refuses to produce misleading results.

`77` drew random null drugs with an evolving RNG state and did not store null source IDs. The new null uses a deterministic seed **per pair** and so is a new null draw **on the same held-out pairs**, not an identical reproduction of `77`'s `r_null` columns. Nearest, mean and distance-weighted predictors are fully reused.

## Interpretation / experimental precautions

1. **Same pairs, different measurement resolution.** Higher `activity_r` than `gene_r` may simply reflect denoising and fewer features. Do not declare activity transfer biologically superior based solely on median r. Compare each representation to its own same-line reproducibility ceiling (when available) and against its matched random-drug null.
2. **The hierarchy does not add prediction capacity yet.** The profile predictions are the original nearest/mean/distance-weighted transfers; our hierarchy only changes evaluation. To demonstrate a predictive gain, subsequently fit a model using the hierarchy and compare predictions on these same held-out pairs.
3. **L1000 coverage.** This benchmark uses the 978 directly measured landmarks. It is intentionally not an evaluation of all ~10,000 measured-plus-inferred genes from your later production pipeline. Low target coverage can bias per-regulon results; report and sensitivity-test minimum targets.
4. **Networks matter.** Your ARACNe networks are disease-specific and do not necessarily encode direct causal regulation. CollecTRI and ARACNe should be benchmarked separately before considering a consensus.
5. **Levels are not directly commensurate.** L1000 level-5 entries are standardized perturbation z-scores; limma disease signed z-scores and VIPER NES are not directly additive fold changes. A separate calibration is required before implementing gene-level tumor-to-healthy rescue distance.
6. **Aggregation is unchanged.** Reusing script `77` intentionally retains its treatment-dose/time pooling and TAS/HiQ filtering. The new benchmark is about *representation*, not dose/time variation.

## Verify installation with synthetic tests

```bash
python -m pytest tests/test_77b_lincs_representation_transfer.py -q
```

These tests check exact pair reuse, recreation of the gene benchmark, signed/overlap weighting, misaligned input rejection, and explicit external activity alignment. Passing synthetic tests is **not** a substitute for running the real LINCS benchmark locally.
